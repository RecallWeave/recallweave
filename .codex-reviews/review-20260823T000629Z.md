### Medium — Valid heading links with noncanonical separator whitespace are rejected

[src/recallweave/parser.py:299](/Users/josh/particle-workers/recallweave/src/recallweave/parser.py:299), [src/recallweave/parser.py:319](/Users/josh/particle-workers/recallweave/src/recallweave/parser.py:319), [src/recallweave/parser.py:406](/Users/josh/particle-workers/recallweave/src/recallweave/parser.py:406), [src/recallweave/contract.py:423](/Users/josh/particle-workers/recallweave/src/recallweave/contract.py:423)

`HEADING_RE` accepts one or more whitespace characters between the heading markers and text. The indexer therefore produces genuine authored edges for headings such as:

```markdown
##  Related [[Target]]
##	Related [[Target]]
```

`note_headings`, however, stores only `level` and normalized `text`. `_matching_links_in_heading` reconstructs the line with exactly one ASCII space:

```python
"#" * level + " " + text
```

The persisted edge retains the actual stripped source line, so equality fails and the exporter rejects an indexer-produced edge.

Parser-level reproduction against the current tree:

```text
'##  Related [[Target]]'
HeadingRef(line=1, level=2, text='Related [[Target]]')
LinkEvidence(... text='##  Related [[Target]]')

'##\tRelated [[Target]]'
HeadingRef(line=1, level=2, text='Related [[Target]]')
LinkEvidence(... text='##\tRelated [[Target]]')
```

Both reconstruct as `'## Related [[Target]]'`. This fails closed and does not authenticate forged evidence, but it is the third genuine-edge false rejection on this route. It also disproves the claim that the complete physical heading line is reconstructed.

`note_headings` is otherwise the correct architectural shape: headings have a lifecycle independent of body-driven sections. It is incomplete for exact-line authentication because it does not preserve the separator or exact raw heading line.
