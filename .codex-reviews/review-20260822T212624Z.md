## 1. Findings

### High — connection-evidence citations are neither verified nor included in provenance

`docs/task-contracts.md:27-31`, `ARCHITECTURE.md:36-42`, and `docs/task-contracts.md:199` promise that every citation resolves to physical vault lines and that `provenance.citations` lists every citation in document order.

The implementation does not enforce either property:

- `src/recallweave/contract.py:141-166` accepts any string as `source_evidence.citation` or `target_evidence.citation`.
- `connection_evidence_is_well_formed()` checks only that the citation is a string; it does not resolve or validate its path or line range.
- `src/recallweave/contract.py:493-499` builds `provenance.citations` solely from constraints, prior decisions, and retrieved context. It omits citations emitted inside connection evidence.
- The existing malformed-evidence fixtures themselves demonstrate that an arbitrary citation such as `"x"` passes the citation-type portion of validation when accompanied by a passage.

Concrete failure scenario: a persisted discovery edge contains:

```json
{
  "shared_terms": ["zephyr"],
  "source_evidence": {
    "citation": "Nonexistent.md:999-1000",
    "passage": "purported evidence"
  }
}
```

The contract accepts and emits that citation, while `provenance.citations` omits it. A receiving agent therefore sees purported cited evidence that RecallWeave neither resolves nor records in the claimed complete citation inventory. This violates evidence integrity and the documentation’s positive verification claims.

### Medium — CHANGELOG overstates the fail-closed validation boundary

`CHANGELOG.md:21-24` says the builder validates “every connection before the budget is consulted.”

Actual behavior at `src/recallweave/contract.py:471-489` validates the current edge, consults the budget, and then `break`s. Later edges are never examined. The new test at `tests/test_contract_document.py:1286-1354` correctly and explicitly proves that the export is not a whole-index validation, but the CHANGELOG still makes the opposite claim.

This matters operationally: a malformed edge after the budget boundary can remain undetected during a successful export. The returned connections are validated; the entire eligible edge set is not.
