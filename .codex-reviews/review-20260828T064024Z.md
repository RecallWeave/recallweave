## 1. Findings

### High — Cold Trails is not deterministic for the same graph and feedback

[viewer/app/cold-trails.ts](/Users/josh/particle-workers/recallweave/viewer/app/cold-trails.ts:454) calls `Date.now()` while scoring candidate trails. Dormant selection also defaults to the current wall clock at [cold-trails.ts](/Users/josh/particle-workers/recallweave/viewer/app/cold-trails.ts:676).

Consequences:

- Identical graph and feedback inputs can produce different scores, ordering, eligibility, and structural facts depending on invocation time.
- A note crosses the 180-day Dormant threshold without any graph change.
- Candidate scores continuously change through `ageBonus`.
- Multiple `Date.now()` calls within one build do not even share a single reference instant.

This directly violates the explicit contract in [docs/cold-trails.md](/Users/josh/particle-workers/recallweave/docs/cold-trails.md:101): “For the same graph and feedback state, scoring and selection must be identical.” It is a reproducibility failure and therefore blocks PASS.

### High — Explain renders unverified evidence claims as validated facts

[viewer/app/graph-data.ts](/Users/josh/particle-workers/recallweave/viewer/app/graph-data.ts:184) sanitizes imported `shared_tags` and `mutual_neighbor_ids` syntactically but preserves them without checking that:

- the tag exists on both endpoint nodes;
- the claimed neighbor exists;
- the claimed neighbor is mutually adjacent to both endpoints.

The scorer correctly revalidates these claims at [viewer/app/cold-trails.ts](/Users/josh/particle-workers/recallweave/viewer/app/cold-trails.ts:386), but the Explain UI bypasses those validated values and renders the original input directly as “Shared tag” and “Mutual neighbor” at [ColdTrailsTour.tsx](/Users/josh/particle-workers/recallweave/viewer/app/components/ColdTrailsTour.tsx:380).

Failure scenario: an untrusted graph supplies `shared_tags: ["fabricated"]` and `mutual_neighbor_ids: ["missing.md"]`. Those claims do not increase the score, but Explain still presents them as evidence. This crosses the project’s supporting-evidence boundary and conflicts with the browser trust model that graph JSON is untrusted input.

### Medium — Timestamp validation does not enforce the frozen viewer.v2 format

`safeIsoTimestamp()` accepts anything JavaScript’s implementation-dependent `Date.parse()` recognizes and returns the original string unchanged at [viewer/app/graph-data.ts](/Users/josh/particle-workers/recallweave/viewer/app/graph-data.ts:152).

The frozen schema requires UTC ISO-8601 timestamps at [docs/json-output.md](/Users/josh/particle-workers/recallweave/docs/json-output.md:332). Inputs such as locale-formatted dates, date-only strings, or timestamps without a timezone may therefore enter temporal classification. Parsing can vary across runtimes or use local timezone assumptions, undermining consistent Dormant and Parallel-invention behavior.
