## 1. Findings

### High — Inline Markdown remains executable rendering syntax

`src/recallweave/contract_markdown.py:18-44` escapes HTML and leading block characters but does not escape inline Markdown constructs. User- and vault-derived values can therefore create links, images, autoloaded remote resources, and inline formatting.

Affected routes include:

- Objective: `contract_markdown.py:109-117`
- Acceptance criteria: `contract_markdown.py:120-131`
- Connection source, target, and kind: `contract_markdown.py:175-190`
- Exclusions and provenance citations: `contract_markdown.py:194-240`

Reproduction against the current tree produced:

```markdown
Review ![tracking](https://attacker.example/pixel) and [click](javascript:alert(1))

- [ ] AC1 Load ![beacon](https://attacker.example/leak)

| ![edge](https://attacker.example/edge) | B | [run](javascript:alert(2)) | false |
```

A Markdown consumer may fetch the remote images, leaking that the artifact was opened and potentially exposing URL-embedded content. It also contradicts the security promise that untrusted text is rendered as data.

The remediation prevents block-structure injection and fence escape, but it does not close the original rendering-safety finding completely.

### High — Cited constraints and prior decisions can exceed the character budget

In `src/recallweave/contract.py:222-237`, the code:

1. Checks only `operator_cost` against the budget.
2. Then adds cited passages to `used`.
3. Does not reject or truncate when that pushes `used` beyond `max_characters`.

The resulting contract can report `truncated: false` while `characters_used > character_budget`, violating `docs/task-contracts.md:195-199` and `docs/json-output.md:86`.

Filesystem-free reproduction using mocked retrieval:

```text
{'character_budget': 10, 'characters_used': 17, 'truncated': False}
emitted_count= 17
```

The input contained a one-character objective and an eight-character cited constraint emitted as both `statement` and `passage`.

Connection evidence is now budget-gated correctly, but the document-wide budget invariant remains false.
