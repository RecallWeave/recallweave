### High — “well-formed” remains undefined and its enforcement is vacuous for conditional connection evidence

[docs/task-contracts.md](/Users/josh/particle-workers/recallweave/docs/task-contracts.md:375) defines well-formedness as including every projected key “that applies to an item’s evidence class,” but never specifies which evidence leaves apply to `authored_link` versus `discovery_candidate`.

The claimed enforcement does not establish that condition:

- [test_contract_document.py](/Users/josh/particle-workers/recallweave/tests/test_contract_document.py:238) derives applicability from whether the evidence is already present.
- Missing `shared_terms` always passes because the test only checks its type if it exists.
- Missing `source_evidence` or `target_evidence` always passes because leaves are checked only if the side dictionary exists.
- The test never branches on `conn["evidence_class"]`.
- It exercises only one `_full_spec()` result rather than all publicly obtainable connection shapes.

Consequently, a connection with either evidence class and an empty `evidence` object passes every conditional well-formedness check. The condition is therefore not independently checkable and cannot support the injectivity claim. “Present exactly when they apply” at [docs/task-contracts.md](/Users/josh/particle-workers/recallweave/docs/task-contracts.md:387) is asserted rather than tested.

This is a contract/evidence-integrity defect: readers cannot determine document validity without reverse-engineering `_edge_evidence`, and even the named test cannot reject a purportedly malformed conditional shape.

### Medium — the projection privacy test misses four of ten omitted fields

[test_contract_projection.py](/Users/josh/particle-workers/recallweave/tests/test_contract_projection.py:765) searches for textual sentinels such as `NPS_LINESTART`, but [the population helper](/Users/josh/particle-workers/recallweave/tests/test_contract_projection.py:816) injects different values:

- `line_start`: injects `1111`, searches for `NPS_LINESTART`
- `line_end`: injects `2222`, searches for `NPS_LINEEND`
- `truncated`: injects `True`, searches for `NPS_TRUNCATED`
- `verified`: injects `"NPS_VERIFIED"` correctly

Thus a renderer change that emitted `line_start`, `line_end`, or `truncated` would not necessarily fail the test. Boolean fields are especially unsuitable for arbitrary string sentinels because a renderer may legitimately serialize them as `true`/`false`.

The current renderer does not emit these fields, so this is presently a test-quality defect rather than an observed privacy leak.

### Medium — documentation claims projected-set agreement that no test performs

[docs/task-contracts.md](/Users/josh/particle-workers/recallweave/docs/task-contracts.md:293) and [test_contract_projection.py](/Users/josh/particle-workers/recallweave/tests/test_contract_projection.py:121) say the documented projected list and `PROJECTED_FIELDS` are compared so they cannot drift.

The prior `_documented_projected_fields()` comparison was removed. The replacement parses only the not-projected section. The two projected lists can now drift while all tests pass—the precise self-referential coverage weakness this remediation intended to eliminate.
