### Medium — Portability scanner ignores format specifications on unconverted booleans

In `tests/test_contract_markdown_injection.py:1323-1324`, `_format_static_value()` returns `"True"` or `"False"` for boolean constants without applying `format_spec`.

Python treats booleans as integers for numeric formatting. Consequently, the portability oracle misses Windows device filenames constructed this way.

Reproduction on the current tree:

```text
f"COM{True:d}.md"   actual= 'COM1.md' scanned= ['COMTrue.md', ...]
f"COM{True:01d}.md" actual= 'COM1.md' scanned= ['COMTrue.md', ...]
```

`COM1.md` is a reserved Windows device filename, but the scanner believes the fixture is `COMTrue.md`. This is the same invariant gap the cycle-24 remediation is intended to close.

The remediation should apply `format(value, spec or "")` for unconverted booleans, as it does for integers, while preserving the current `"True"`/`"False"` result when no specification is supplied.
